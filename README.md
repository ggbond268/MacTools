> **Window positioning:** The standalone Command Palette and resizable Clipboard History window provide dedicated drag handles, guide-assisted dragging, and magnetic snapping to their current-size default screen anchors. The palette also provides a searchable command that resets its saved position. Dismissing the Command Palette cancels an active drag and immediately hides its guides.

> **Window Switcher:** The catalog includes eligible windows from inactive macOS Spaces, so switching does not depend on the current Space.

> **Preferences sync:** Sync portable preferences through iCloud Drive or a custom shared folder. Manual exports and sync documents are interchangeable. Cloud updates preserve device-local rules, shortcuts, Run Links, hardware settings, and their workflow dependencies; plugin settings required by those local dependencies stay on this Mac. Concurrent changes pause synchronization and offer a choice between local and shared settings, with both versions saved locally. Pending edits survive restarts and are reconciled before publication; quitting does not overwrite the shared file. Sync waits for plugins to finish loading and supports retry after file errors. A missing established shared file pauses sync until it becomes available again.

> **Shortcut settings:** Plugin and app shortcut rows keep the action icon/name beside the recorder field, wrapping groups between rows without splitting an individual shortcut control.

> **System Status:** Both dashboard entry points keep readings current while open. Detail statistics use all retained readings in the selected range, independent of chart simplification, and pinned readings stay fixed until they leave that range. Expanded metric settings adapt to narrower windows. An optional global shortcut shows the menu-bar overview when available and otherwise opens the dashboard. The PluginKit v6 package requires MacTools 1.3.0 or later.

> **Settings sidebar states:** The open page uses native macOS selection, keyboard search candidates use a focus outline until opened, and collapsed sections containing the open page use a separate accent marker. The plugin settings sort icon follows its section title color while the menu retains its native appearance.
>
> **Pre-install plugin metadata:** The signed plugin catalog can disclose localized product details, requirements, privacy behavior, setup guidance, and static or dynamic action capabilities before a plugin is installed. The same validated metadata is available to Marketplace, search, onboarding, and website clients without loading plugin code or publishing machine-local action entries. Open a catalog detail page with `mactools://app/settings/plugins/marketplace/<plugin-id>`; append matching `provider` and `action` parameters only to highlight a published static action. These links navigate only and never install or run a plugin action.

> **Menu-bar panels:** The top-right door-and-arrow button quits MacTools. Keep Awake duration options fit within their feature row when expanded. Use Edit Layout in the leading toolbar to reorder visible Dashboard cards or Feature Panel rows. Cards and rows stay in place during dragging, with a stable insertion marker and edge scrolling. Each item also offers a move menu with keyboard and VoiceOver support. Completed moves save immediately and stay in sync with Settings. Use Undo to restore the last move and Done to finish; cancelled or outdated drags show feedback. Escape first exits editing, and switching tabs or closing the panel ends editing. Settings remains the place to show hidden items or reset an order. Dashboard cards and their nested controls use shared semantic surfaces and text levels in Light, Dark, and Increased Contrast appearances, without decorative borders or shadows. The surrounding popover and its attachment arrow use one opaque semantic background so wallpaper colors do not reduce contrast. Settings includes independent Light and Dark themes, ten built-in palettes, System Default, live previews, and imports from `.itermcolors` (including `.txt`) or Base16/Base24 YAML/JSON files; themes preserve layout, typography, calendar event colors, and brand colors.

> **Preferences backup:** MacTools automatically keeps a local, deduplicated history of portable settings, with a 60-second debounce, a pre-import safety snapshot, human-readable local date-time filenames, and bounded hourly/daily/weekly retention. Each importable backup is limited to 16 MiB, while automatic history is capped at 100 snapshots and 128 MiB. Only successful saved portable-setting changes start or restart the timer; runtime history and cache writes are ignored. Automatic backup is enabled by default and can be disabled, run immediately, or opened in Finder from General settings, which also shows relative backup freshness, the exact timestamp, snapshot count, history size, and whether a manual backup found no changes. Export and import both let you select app preferences, plugin layout, shortcuts, automation, saved Run Links, and each plugin’s portable settings independently, with dependency notes beside every category. Saved action shortcuts and Run Link presets are filtered independently for portability, including when only one category is selected. Workflow IDs and direct workflow Run Links are preserved; importing an individual workflow preserves its ID on a new Mac and creates a new ID only when that ID already exists. Automation rules bound to a display identifier from the current Mac are omitted with an export warning. Saved Scripts source is excluded unless each script explicitly opts in, and working directories are never included. Apple Shortcuts backup includes only per-shortcut safety policies; the destination Mac discovers its own current Shortcuts library. Permissions, caches, credentials, and other non-portable data are excluded. The import preview preselects missing catalog-verified plugins, offers Select All and Deselect All, and preserves unchecked choices while categories change. Installation starts only after confirmation, with progress shown for each plugin. If a newly installed plugin requires a restart, the result asks you to restart MacTools and import the backup again to restore its settings; these instructions are shown separately from restore failures.

> **Mac Settings search:** Ranked results stay directly below the search field, including searches that return only one or two settings. Category actions use the visible search instead of a removable scope strip, and exact-setting actions scroll to and focus their target row.

> **Right-click action:** You can use Option + left-click on the MacTools icon to trigger the right-click action.

> **Deep links and Run Links:** Open MacTools surfaces or invoke explicitly eligible actions and workflows through the guarded [`mactools://app/...` URL API](docs/url-scheme.md).

Clipboard identifies Universal Clipboard captures as Other Device, shows Universal Clipboard in details, and respects explicit source-app markers. Empty, invalid, or conflicting source markers remain Unknown Source; unmarked local copies retain the foreground-app estimate. Source metadata survives saving, reopening, and backup restoration without changing existing records. Merging older backups retains known Other Device sources. Clipboard History searches snippet names, tags, keywords, and content together. Pasted multiline searches stay on one readable line, and line breaks, tabs, and spaces match the same stored content. Two-character searches also match inside words, so `88` finds `MT88 tripod`. Plain-text paste derives complete visible text from safely importable rich clipboard content, while normal paste preserves every original representation; oversized or unreadable rich data falls back to the producer's plain text. Snippet exports use the same formats from the Actions panel and context menu, and snippet storage failures provide recovery feedback without hiding usable history. Pausing collection cancels pending captures; pasting from history, snippets, combined selections, or the plain-text shortcut cancels if another copy replaces the prepared clipboard before paste dispatch. New copies also end implicit paste queues. Pending snippet saves are cancelled on deactivation and cannot recreate storage after uninstall. Snippet cursor placement is best-effort and leaves subsequent typing or focus changes alone. In multi-select mode, Command-A still selects search text, while customizable Option-Command-A selects every visible clipboard item without moving focus. Clipboard settings group History, Snippets, and Paste Queue controls by feature, with infrequent options in each section’s Advanced disclosure. Privacy & Storage appears first in History. Excluded apps, private-copy shortcuts, and window shortcuts follow in Advanced, while Local Data keeps direct History, Saved Clips, and Snippets cleanup actions. Settings search reveals and expands the matching shortcut group, including Clipboard Window Shortcuts and Paste Queue controls, without collapsing sections already opened.

Clipboard save, unsave, and item edits commit in order without interrupting new copies or image text recognition. Actions remain tied to the items they opened for and close when that selection becomes invalid. Action shortcuts work inside the companion search while preserving text-editing shortcuts. Literal snippets do not read the system clipboard; clipboard variables read asynchronously and reject stale or oversized results. Large snippet collections reuse prepared search metadata, including fast near-miss searches. A manual Clipboard write ends an implicit paste queue immediately; explicit queues are preserved.

Clipboard → Local Data includes **Back Up Clipboard Data…** and **Restore Clipboard Backup…** for password-protected `.mactoolsclipboard` archives. Choose the backup file or save location before entering a password of at least 12 characters for new backups; creation and restoration require an explicit action, and completed operations show only Done. Saved Clips and Snippets are selected by default; History requires explicit consent with its count, estimated size, and privacy warning. Restore validates before preview, defaults to merge, preserves conflicting IDs, and disables conflicting snippet keywords. If merged keyword snippets exceed capacity, confirmation explains that local keywords take priority and excess imported keyword bindings are removed in backup order while all snippet content is kept. Precisely scoped replacement creates a recoverable local rollback snapshot and commits atomically. Missing file paths and conflict details remain available in paged reports after restoration. Failed or cancelled recovery preserves the previous rollback. Backup work pauses clipboard actions and the paste-queue HUD while preserving pending Private Copy protection; restored History retains its initial contents until a new copy or retention-setting change. Preferences Backup and readable per-item Export remain separate. See the [backup format and security review](docs/superpowers/specs/2026-09-07-clipboard-backup-security.md).

Clipboard uses vertically centered list icons and a 40/60 list-to-preview split. Footer buttons share subtle hover feedback; the compact collection icon retains a full click target and uses the system accent color when collection is disabled. Clipboard prepares its first page in the background after storage loads and opens without a window transition. Manage Snippets opens the Snippets scope even while preparation is pending or the library is empty. Reopening reuses an unchanged initial page, and metadata-only updates patch affected results without resetting selection or rerunning unrelated searches. Image/PDF previews use a bounded, window-scoped thumbnail cache; the most recent bounded rich-text preview also survives ordinary closes without rereading or importing its source. Selecting an already-visible row no longer centers it unnecessarily. Synthetic model, preview, and native-window benchmarks are available under `scripts/benchmarks/` without reading the system clipboard or the user's database.

## Install

```bash
brew install --cask mactools
```

### Nightly builds

When a public Nightly release is available, download `MacTools-Nightly.dmg` from the newest [`nightly-*` prerelease](https://github.com/ggbond268/MacTools/releases). Nightly is an unstable, separately signed app with its own settings, URL scheme, update feed, and same-commit plugin catalog, so it can be installed beside stable MacTools. Do not rely on it for critical workflows; published Nightly assets are retained only for a bounded period.

Nightly uses separate privileged helper installations for Fan Control and Battery Charge Limit, and separate Keychain services for Translator and Cloudflare R2. Configure Nightly credentials separately; stable credentials are not copied or modified. The physical hardware is still shared, so avoid applying competing fan or charging policies from both apps at once. Scheduled runs skip publication when the source is unchanged apart from generated Nightly metadata; manual runs can always force a new build.

Activity Bar uses separate Nightly hook scripts and a separate socket, so installing or removing one channel's hooks leaves the other channel's hooks intact. The Nightly CLI broker also uses its own service and signing identity. Shared hardware controls and the trackpad's single-listener lock remain shared intentionally.

### Experimental command-line prototype

General settings identifies the command-line switch through its title and status description, without a separate Enable caption.

The Command Line section is at the bottom of General settings. It keeps status and the connection permission visible, with paths and terminal setup under Details and removal/rollback under Manage. Click anywhere on the Details or Terminal setup header to expand or collapse it. On Apple silicon, signed Nightly builds with installation metadata offer **Settings → General → Command Line → Install CLI…**. One confirmation shows the matching download, paths, integration choice, and explains that the CLI updates automatically with MacTools. The per-user `~/.local/bin/mactools-nightly` command supports managed updates, removal, and rollback. Managed installations follow app updates automatically, including installations with the old update preference disabled. An explicit rollback is retained across restarts until the next app release or an explicit Update. If macOS has not cached the CLI’s notarization ticket, installation requests a Gatekeeper assessment and rechecks the full signature before running the CLI. If verification still fails, installation stops with retry guidance. Interrupted cleanup resumes on the next launch or managed operation. Retry preserves the failed operation and its choices, including removal and rollback; installation prompts and errors follow the selected app language. Existing manual, Homebrew, stable, and other publisher installations are preserved; MacTools never edits shell startup files or installs a CLI without consent. Older Nightly builds continue to support manual installation.

Stable CLI support is prepared for Apple silicon and the app's minimum macOS version. Signed stable candidates with sealed installation metadata offer the same optional installation flow, using `~/.local/bin/mactools` and a separate managed store. Nightly keeps its own command and installation. Stable CLI publication remains disabled pending signed acceptance; ordinary stable releases do not yet offer managed installation. See the [stable proposal](docs/cli/proposals/stable-cli-v1.md) and [candidate release procedure](docs/plugins/cli-release.md).

Nightly releases provide a separately downloadable `mactools` prototype for testing; it is not embedded in the app. It provides `help`, `version`, `doctor`, read-only action discovery, and Phase 2 execution with `actions run <id>`. Execution is limited to actions described as execution-supported: safe, background, automatic, portable, truly parameterless actions that the host revalidates immediately before running. Commands support human-readable or `--json` output, bounded timeouts, and Ctrl-C cancellation. Typed parameters and saved presets remain unsupported. Follow the [Nightly download and installation guide](docs/testing/cli-nightly-distribution.md), use the [AI-agent usage guide](docs/cli/agent-usage.md) for bounded local agent experiments, or use the [Phase 2 source-build guide](docs/testing/cli-phase-2.md) when developing the CLI itself.

## Upgrade

MacTools 1.3 uses PluginKit v6. Its plugin packages require MacTools 1.3.0 or later; update installed plugins to the compatible versions after upgrading. Earlier app releases retain their existing plugin catalogs.

```bash
brew update
brew upgrade --cask --greedy mactools
```

MacTools quietly checks for app updates once per day. When an update is available, the menu-bar panel shows an Update button beside Settings; selecting it opens About and starts the standard Sparkle update flow.

The in-app update dialog separates App Updates from Plugin Updates and includes plugin releases published since the previous app version.

About keeps the app summary and update action visible above a scrollable, offline history of the 10 most recent App and Plugin releases.

If Homebrew still reports that the cask is already up to date, check the locally resolved cask version first:

```bash
brew info --cask mactools
```
